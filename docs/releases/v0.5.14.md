# claude-peer v0.5.14

## SDK 0.5.16 refusal clarification

The Go SDK is pinned directly at v0.5.16. Shared support stays at the actual reviewed common commit `29ddcb4585deaffc637163381ea1bce4a312e237`; the direct SDK requirement selects v0.5.16 over that common revision's older minimum. No product hello, filesystem, cwd, permission or lifecycle mechanism is added.

The SDK reports `unknown_transfer` for a missing local transfer binding and for an ended binding after its existing earlier checks. Existing path, field, role and overwrite checks keep their current precedence and conflict refusals. On a local daemon upgraded to Sessionbus v0.5.16, the SDK's existing hello paths opt in to `unknown_transfer` (-32020) for a status request with no accessible live transfer, including an absent or ended ID. An older daemon keeps `transfer_failed` (-32019); the SDK accepts that legacy answer too. An old daemon can expose the extra hello info key as ordinary public metadata.

The new wire answer applies only to local status replies. Wire Accept/Cancel and federation keep their existing answers. Status still does not return or preserve a completed outcome, file hash or terminal history. A missing final notice does not prove failure or make replay safe. Files are still read and written directly as the OS user, with no sandbox or native approval per path. Tightening transfer permissions later remains OPEN and is not a release gate.

## Carried source behavior and historical evidence

The source changes below were already merged for the unreleased v0.5.13 candidate. Its existing [v0.5.13 note](v0.5.13.md) is unchanged; these descriptions carry that implementation and its limits forward, with the intended dependency/release labels updated. Its source/unit evidence is historical and does not establish SDK16 native acceptance.

This release lets managed Claude sessions and Claude lanes send and receive files through the `sessionbus` tool. Transfers need Sessionbus v0.5.14 or newer on every involved host, including the hub for transfers between hosts, and refusal-aware SDKs or kits on both endpoints. The Go SDK is pinned at v0.5.16; peer-common is pinned at `29ddcb4585deaffc637163381ea1bce4a312e237`. Native Claude remains installed separately.

- The shared tool gains `transfer.offer`, `transfer.request`, `transfer.accept`, `transfer.cancel` and `transfer.status`, with the unchanged common declaration. Each interactive native-session resident owns one SDK manager; lanes use the existing Worker's bound caller.
- Files of up to 1 GiB are read and written as your OS user. A received file is published only after its SHA-256 matches; an existing destination is replaced only with `overwrite: true`.
- **No permission layer of its own.** After a Sessionbus tool call is admitted, the SDK accesses files without applying the Claude sandbox and without asking for a native approval per path. Existing managed Sessionbus tool grants remain unchanged.
- Relative local paths use the same common helper as the shipped Codex binder. Interactive actions read cwd only from the existing bounded native registry reader for the captured live parent/session/socket. If that registry witness is missing, stale or has no absolute cwd, only absolute paths work. The helper process directory is never used as the interactive session directory. Lanes use their native launch directory. Symlink and `..` spelling is preserved; case-fold path-key aliases are refused.
- Offers, requests and final results use the existing ordinary delivery path. Final results add only the endpoint's local projection. Projection waits off the RPC reader, so another ordinary message may arrive before a held final notice.
- A final result is not kept for reconnect or sent again, so a connection failure can lose it. A missing final result does not show that the transfer failed or that a retry is safe: the file may already be at its destination. Owner/session exit cancels and joins SDK transfer generations before disposal; already-attempted actions are never replayed.
- Valid transfer refusals preserve the caller connection, including `unsupported_transfer` and `transfer_failed`. Federation availability and policy support come from the updated SDK.
- `RELEASE_VERSION` and the Claude plugin manifest become 0.5.14. The skill change only extends its opening action-name list; no trust, authority or other instruction is changed.

Source/unit/race and existing package checks are recorded at the exact final candidate. Native U-series and installed idle/busy/lane acceptance are separate required evidence before publication; this prepared note makes no unrun native, model, matrix or readiness claim. Existing native behavior and known limitations remain attributed to their retained evidence.

The owner reports existing native authorization on UMKA. It is a precondition available for later Root-coordinated validation after repin, not a new model or transfer PASS.
